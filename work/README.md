# خط أنابيب استخراج نص الكتابين

محرّك تفريغ مخصّص للكتابين:

- `كتاب رتل مصمم ver3 - Part2.pdf` (63 صفحة)
- `كتاب رتل مصمم ver3 - Part3.pdf` (32 صفحة)

## المشكلة

النص العربي في الكتابين مكتوب بخطوط CID بصيغة `Identity-H`: تيار المحتوى
يحفظ **أرقام الرسوم** لا الحروف، والترتيب فيه ترتيبٌ مرئي، فلا تكفي أي
مكتبة استخراج جاهزة. والمصادر المتاحة لحلّ الرموز ناقصة:

* خريطة `ToUnicode` التي كتبها Word صحيحة جزئيًّا فقط — خاطئة للأشكال
  السياقية في خط SakkalMajalla، وخاطئة لمعظم علامات الضبط في الخط
  القرآني KFGQPC (مثلًا رسم المسافة ← `ۡۖ`).
* أسماء الرسوم في الخط المضمّن عامة (`glyph02221`) أو سياقية
  (`afii57416.init`) أو مركّبة (`afii57444.init_afii57411.zz04`).

## المكوّنات

| الملف | الوظيفة |
| --- | --- |
| `decode_driver_v2.py` | **السائق النهائي**: يجمّع الرموز في عناقيد وأسطر بترتيب منطقي RTL، ويحافظ على مسارات الأرقام واللاتيني بترتيبها LTR |
| `pdf_decoder.py` | محلّل تيارات المحتوى (`Tj/TJ/Tm/Td/TD`) مع تتبّع مواضع الرموز |
| `cmap_parser.py` | محلّل خرائط ToUnicode المضمّنة في PDF |
| `font_fixer.py` | حلّ الرموز: اسم الرسم ← الخط الكامل بنفس رقم الرسم ← الرسوم المركّبة ← مطابقة الأشكال |
| `reverse_resolver.py` | مطابقة الأشكال (عكس GSUB احتياطي) — أدوات مساعدة |
| `fetch_fonts.py` | تنزيل الخطوط المرجعية إلى `work/fonts/` |
| `decode_driver.py` | **الإصدار 1 (مهمل)**: المرحلة الأولى من العمل، محفوظ للرجوع إليه فقط |

## التشغيل

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
python fetch_fonts.py                 # ينزّل الخطوط المرجعية (مرة واحدة)

python decode_driver_v2.py "../cmd/كتاب رتل مصمم ver3 - Part2.pdf" part2_final.txt
python decode_driver_v2.py "../cmd/كتاب رتل مصمم ver3 - Part3.pdf" part3_final.txt
```

يعمل الأمر من أي مجلد (المسارات الداخلية مبنية من مسار الملف نفسه)،
والخرج حتمي: إعادة التشغيل تُنتج نفس الملفين حرفيًّا.

بدون الخطوط المرجعية يعمل السائق أيضًا، لكن بحلّ رموز أقل؛ ويطبع:
`!! reference font missing: … (run work/fetch_fonts.py)`.

## الخطوط الخارجية (لا تُلحق بالمستودع)
